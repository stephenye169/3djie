# 青果巷 · 3D 虚拟商业街（Street_Empire）

基于 **Three.js + Node.js (Express / WebSocket / SQLite)** 构建的 3D 多人在线商业街漫游与商战模拟 Demo。  
玩家可在按常州青果巷真实空间序列生成的 3D 街区中自由探索、进店消费、收购商铺、发起资本踢馆与议价收购，并支持多房间分流与全服统一经济世界。

> 📌 **提示**：当前默认建筑与角色为**程序化生成低多边形模型**（零外部资产依赖，首屏秒进），同时支持按建筑或整场景替换为 Blender 导出的 `.glb` 模型。

## 核心玩法与特性

- **真实空间序列街区**：按青果巷东→西地标（牌坊、城隍庙戏楼、正素巷、赵元任故居、天井巷、雪洞巷、西入口等）布局约 **55 栋**程序化建筑，其中包含 **18 家可收购商业资产**，全部可推门进入（未收购也能进店逛，点柜台打开收购面板）。
- **第三人称漫游与地图总览**：支持 Pointer Lock 视角、冲刺、6 分钟昼夜光照循环，以及 `M` 键类地图 3D 斜俯视总览（支持平移缩放、屋顶店名定位、我的位置标记、路线预览，以及点击标签或建筑飞到店门口传送，每次消耗 ¥10 万）。
- **多层商业经营（单机→商战）**
  - **三档 18 家资产**：普通（7 家，¥50 万–500 万）、精品（7 家，¥2000 万–100 亿）、黄金（4 家，¥500 亿–5000 亿），持有即每秒自动结算租金，支持 5 级装修。
  - **资本踢馆 & 在线议价（PvP）**：对他人店铺发起恶意收购（1.5× 身价），防守方有 **15 秒**决定「1.5× 护盘（触发钞票雨特效）」、「认栽」或「讨价还价（1.2–2.0×，每场一次）」。普通店铺享有易主 4 小时 + 新手安全期保护，所有店铺踢馆后进入 5 分钟全服保护期。
  - **众筹扩建与分红**：tier ≥ 2 店主可发起扩建众筹，其他玩家入股后可按比例分享该店 40% 的长期租金分红。
  - **街头经济与逆袭引导**：新账号注册初始资金 **¥50 万**，开局逆袭剧情支持一次性空投 **¥5,000 万**体验资金；街头设有金币雨、财阀宝箱（¥80 万–200 万）、沿街巡逻的碰瓷 NPC、5 个商业任务、离线衰减分红与全服首富膜拜红包。
  - **资本轮回（Prestige）**：总身价 ≥ 500 亿可清零重生兑换「传世黑卡」，点亮 3 棵永久天赋树（点金手 / 资本压制 / 躺平收租）。
- **多人在线与多房间分流**
  - **分房不分资产**：WebSocket `/chat?room=N` 支持 1–10 号房（每房 ≤30 人）分流渲染与位置同步，自动记住上次房间；但全服 18 家店铺归属、保护期、首富榜与全服战报弹幕**全局同步**。
  - **双频道社交**：支持全服广场频道与一对一私聊；既可在街上近距离（4 米内）点击角色快捷发起私聊，也可在 Tab 聊天面板在线列表直接点选任意玩家开启会话（不限距离与室内外场景），并支持资料卡、拉黑与勿扰（DND）模式。
  - **管理员后台**：`/admin.html` 支持系统公告发布，后端提供用户禁言管理接口。

## 快速开始

### 环境要求

- **Node.js 18+**
- 现代桌面浏览器（需支持 WebGL 与 Pointer Lock）

### 本地运行

```bash
# 1. 安装依赖
npm install

# 2. 启动后端（默认端口 3003，数据自动生成于 data/qingguo.db）
npm run server

# 3. 另开一个终端启动前端（默认端口 5177，代理 /api 与 /chat 到 3003）
npm run dev
```

其他常用命令：

```bash
npm run build     # 生产构建，输出至 dist/
npm run preview   # 预览生产构建产物
npm run stress    # 后端 10 房间 × 30 人模拟压测（建议配合 DB_PATH 隔离测试库）
npm run fps       # 启动本机 Chrome 实测 30 人同房帧率
```

### 常用入口与联调技巧

| 用途 | 地址 / 操作 |
| --- | --- |
| 进入游戏 | `http://localhost:5177` |
| 多客户端本地联调 | 登录态存放在 `sessionStorage`，新开浏览器标签页即为独立玩家；若复制标签页导致共享会话，访问 `http://localhost:5177/?fresh` 强制新建账号 |
| 系统公告后台 | `http://localhost:5177/admin.html`（默认种子账号 `admin` / `admin123`，可通过环境变量 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖） |

## 操作指南

### 开局选角

加载完成后可选择 **男生「阿青」**（默认，可直接按 `Enter` 开始）或 **女生「小果」**，支持自定义昵称或点击 `🎲` 随机生成江南风词条昵称。

### 快捷键与交互

| 操作 | 说明 |
| --- | --- |
| `W A S D` / 方向键 | 移动角色（`Shift` 冲刺奔跑） |
| 鼠标移动 | 旋转第三人称视角（点击画面锁定指针，`Esc` 解锁） |
| 左键点击店铺 / 图标 | 打开店铺信息卡片（或资产收购/踢馆面板） |
| 左侧资产清单「🌀」按钮 | 传送到该店门口触发圈（与地图传送同价 ¥10 万/次，服务端扣款校验），点击其余区域打开资产卡 |
| 店内点击柜台 / 货架 | 打开**商品卡**：买入商品（进货）+ 本店库存转售；流水进度条展示店铺客流档位 |
| 点 💰 打开个人中心 | 服务端真实账本：余额、背包（进货转售）、购物订单、9 折优惠券 |

**店内消费经济闭环（进货转售）**：玩家在店内「买入」商品（实付计入店铺流水，其中 10% 实时分给店铺收购人——自己买自己店不抽成）→ 背包内商品二选一：⚡ 使用激活增益 / 📜 囤着凑收购资格 / 转售换钱。**转售按实付价 85%~95% 回收（券购商品同样按实付基准），期望为负必亏**——彻底堵死「9 折买入 + 转售」与「双人互刷」正期望套利。商品价格量级与主货币拉齐：日常消费 ¥1.6 万~8 万、功能商品 ¥10 万~40 万、收购资格 ¥20 万~80 万。店铺累计流水达档后门口定期刷新「客源金币」，任何人捡到面额全拿，店铺收购人按档位分成 30% / 50% / 80%。**餐饮店（奶茶/馄饨/咖啡/茶馆/面包/糖水 6 家）客流档位门槛减半**（¥1 万档 ¥2 万即达标）——补偿食品不可转售带来的客流变现下降，体现餐饮业「刚需消耗」的经营差异化。每人每商品每日限购 3 件。

**踢馆托管金安全（重启不丢钱）**：服务启动时自动扫表，把上次进程残留的进行中踢馆托管金原路退回攻击方（状态标记 `refunded`），并补店铺冷却——杜绝"重启后托管金蒸发"。

**商品三类体系（消耗品 vs 流通品，资产去向严格互斥——绝不允许「既用了效果又卖了货」）**：
- 🥤 **日常消费（即食消耗，食品饮品）**：买完立即吃掉/喝掉，buff 即时生效——👟 健步如飞（移动速度 +35%）、✨ 财运暴击（金币雨暴击率 +12%）、🧲 吸金磁铁（拾取半径 +60%）。**不进背包、不可转售**（服务端强制拦截）
- ⚡ **功能商品（进背包，使用制）**：长效增益 10 分钟——📈 日进斗金（收租收益 +25%，服务端结算）、💰 点石成金（拾取金币金额 +30%）、长效版速度/磁铁/暴击。买后进背包，**须在个人中心点「使用」才激活并扣除库存**；未使用的可自由转售——用掉还是卖掉，玩家自己抉择
- 📜 **收购资格（硬通货）**：材料商品，收购 tier≥2 店铺时按清单消耗——商业许可证（金融中心 ¥80 万）、街区信誉章（书店 ¥30 万）、税务合规书（礼和堂 ¥50 万）、装修图纸（记忆馆 ¥20 万）、稀有材料黑胶唱片（赵元任故居 ¥60 万）。可自由转售，收购消耗后自动从背包消失

**分级收购门槛（不能纯靠金币买下全街）**：
- 普通店铺（第一幕 7 家）：仅金币
- 精品店铺（第二幕 4 家）：金币 + 商业许可证 + 街区信誉章
- 高级店铺（第三幕 3 家）：金币 + 四证齐全（许可证/信誉章/税务书/图纸）
- 黄金店铺（第四幕 4 家）：金币 + 四证 + 稀有黑胶唱片 + 持有店铺数 ≥ 3

资产卡收购面板实时显示门槛清单（✅/❌ 逐项），未达标禁止收购；材料在收购成功时消耗，失败不扣。玩家循环成型：**赚金币 → 买商品获得能力/凑资格 → 收购高级店铺 → 赚更多金币**。
| 走进门口光圈 + `E` | 进店浏览商品、购买或与店员对话 |
| 左键点击身边玩家（4 米内） | 发起一对一私聊（若对方为全服首富，可选择「膜拜领红包」） |
| `M` | 切换 / 退出 **3D 地图总览模式**（左键拖拽平移、滚轮缩放、点击店名/建筑飞到门口传送，¥10 万/次） |
| `Tab` | 打开 / 关闭 **聊天面板**（广场公聊 / 在线列表发起或查看私聊 / 玩家资料卡） |
| `T` | 打开 / 关闭 **资本轮回与永久天赋面板** |
| `Esc` | 逐级关闭：聊天 → 轮回面板 → 地图模式 → 对话 → 店铺卡片 → 退出室内 |

## 接入真实 GLB 模型

无需改动业务代码，支持两种方式替换默认程序化建筑：

1. **按建筑逐栋替换（推荐）**：将模型放入 `public/models/`（如 `cafe.glb`），在 `src/data/layout.js` 对应建筑条目加上 `model: 'cafe.glb'`；或将模型按建筑 `id` 命名后通过 `http://localhost:5177/?models=/models` 访问即可自动匹配。加载失败会自动保留原程序化建筑。
2. **整条街替换**：放入 `public/models/street.glb`，通过 `http://localhost:5177/?glb=/models/street.glb` 加载（支持 Draco 压缩，模型命名含 `ground`/`wall`/`shop_<id>` 时会自动识别地面、碰撞体与店铺）。

## 已知限制

- **美术与移动端**：仓库暂未附带真实 `.glb` 模型与贴图资源；交互依赖键盘与 Pointer Lock，暂未适配触屏移动端。
- **单机写库瓶颈**：后端默认使用 `sql.js`（内存库全量导出，现 `server/db.js` 已改为 400ms 节流异步原子落盘，但仍勿多进程同时读写同一 `.db` 文件）；早先同步写盘基准上限约 180–190 次/秒，300 人正常游玩稳定，更高并发需后续切换 `better-sqlite3`（WAL）或 MySQL。
- **多进程扩展**：当前踢馆互斥与房间状态依赖单进程内存，未来横向扩展需接入 Redis 分布式锁与实现 `db.js` 的 MySQL 分支。
- **渲染现状**：角色合批优化后 30 人同房测得 ~51 FPS；街道建筑现已改为轻量化同步构建并按材质合并（`ProceduralStreet.js`），若需在 30 人同房下进一步冲击满帧 60+ FPS，可继续做远端玩家实例化或动态阴影降频。
