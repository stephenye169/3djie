# 青果巷 · 3D 虚拟商业街（Street_Empire）

基于 **Three.js + Node.js (Express / WebSocket / SQLite)** 构建的 3D 多人在线商业街漫游与商战模拟 Demo。  
玩家可在按常州青果巷真实空间序列生成的 3D 街区中自由探索、进店消费、收购商铺、发起资本踢馆与议价收购，并支持多房间分流与全服统一经济世界。

> 📌 **提示**：当前默认建筑与角色为**程序化生成低多边形模型**（零外部资产依赖，首屏秒进），同时支持按建筑或整场景替换为 Blender 导出的 `.glb` 模型。

## 核心玩法与特性

### 街区与漫游

- **真实空间序列街区**：按青果巷东→西地标（牌坊、城隍庙戏楼、正素巷、赵元任故居、天井巷、雪洞巷、西入口等）布局约 **55 栋**程序化建筑，其中包含 **18 家可收购商业资产**，全部可推门进入（未收购也能进店逛，点柜台直接买商品、恢复体能）。
- **第三人称漫游与地图总览**：支持 Pointer Lock 视角、冲刺、6 分钟昼夜光照循环，以及 `M` 键类地图 3D 斜俯视总览（支持平移缩放、屋顶店名定位、我的位置标记、路线预览，以及点击标签或建筑飞到店门口传送，每次消耗 ¥10 万）。

### 多层商业经营

- **四幕 18 家资产**：普通（7 家，¥50 万–500 万）→ 精品（4 家，¥2000 万–2 亿）→ 高级（3 家，¥10 亿–100 亿）→ 黄金（4 家，¥500 亿–5000 亿），逐幕收购门槛递进（详见[分级收购门槛](#分级收购门槛)），持有即每秒自动结算租金，支持 5 级装修。
- **资本踢馆 & 在线议价（PvP）**：对他人店铺发起恶意收购（1.5× 身价），防守方有 **15 秒**决定「1.5× 护盘（触发钞票雨特效）」、「认栽」或「讨价还价（1.2–2.0×，每场一次）」。普通店铺享有易主 4 小时 + 新手安全期保护，所有店铺踢馆后进入 5 分钟全服保护期。
- **众筹扩建与分红**：tier ≥ 2 店主可发起扩建众筹，其他玩家入股后可按比例分享该店 40% 的长期租金分红。

### 街头经济与逆袭引导

新账号注册初始资金 **¥50 万**，开局逆袭剧情支持一次性空投 **¥5,000 万**体验资金；街头设有金币雨、财阀宝箱（¥80 万–200 万）、沿街巡逻的碰瓷 NPC、5 个商业任务、离线衰减分红与全服首富膜拜红包。

### 资本轮回（Prestige）

总身价 ≥ 500 亿可清零重生兑换「传世黑卡」，点亮 3 棵永久天赋树（点金手 / 资本压制 / 躺平收租）。

### 多人在线与社交

- **分房不分资产**：WebSocket `/chat?room=N` 支持 1–10 号房（每房 ≤30 人）分流渲染与位置同步，自动记住上次房间；但全服 18 家店铺归属、保护期、首富榜与全服战报弹幕**全局同步**。
- **双频道社交**：支持全服广场频道与一对一私聊；既可在街上近距离（4 米内）点击角色快捷发起私聊，也可在 Tab 聊天面板在线列表直接点选任意玩家开启会话（不限距离与室内外场景），并支持资料卡、拉黑与勿扰（DND）模式。
- **管理员后台**：`/admin.html` 支持系统公告发布，后端提供用户禁言管理接口。

## 快速开始

### 环境要求

- **Node.js 18+**
- 现代桌面浏览器（需支持 WebGL 与 Pointer Lock）

### 本地运行

```bash
# 1. 安装依赖
npm install

# 2. 启动后端（默认端口 3003，数据自动生成于 data/qingguo.db）
npm run server

# 3. 另开一个终端启动前端（默认端口 5177，代理 /api 与 /chat 到 3003）
npm run dev
```

> 💡 **本地联调**：多开浏览器标签页默认共享同一账号（身份存在 `localStorage`）；需要另起独立玩家时访问 `http://localhost:5177/?fresh` 会清掉本浏览器身份并新建账号。服务健康检查：`curl http://localhost:3003/api/health`。

其他常用命令：

```bash
npm run build     # 生产构建，输出至 dist/
npm run preview   # 预览生产构建产物
npm run stress    # 后端 10 房间 × 30 人模拟压测（建议配合 DB_PATH 隔离测试库）
npm run fps       # 启动本机 Chrome 实测 30 人同房帧率
```

### 常用入口与联调技巧

| 用途 | 地址 / 操作 |
| --- | --- |
| 进入游戏 | `http://localhost:5177` |
| 多客户端本地联调 | 账号与令牌存在 `localStorage`：关闭浏览器再进来仍是同一个玩家（余额 / 店铺 / 背包都在服务端按账号取回）；需要另开一个独立玩家时访问 `http://localhost:5177/?fresh`（会清掉本浏览器的身份并新建账号） |

## 经济与收购体系

玩家核心成长循环：**赚金币 → 进店买商品（获增益 / 凑资质）→ 收购高级店铺 → 赚更多金币**。

### 店内消费经济闭环（进货与转售）

1. **进货与流水抽成**：玩家在店内「买入」商品时，实付金额计入店铺流水，其中 **10% 实时分给店铺收购人**（自己买自己店不抽成）。商品价格量级与主货币拉齐：日常消费 ¥1.6 万–8 万、功能商品 ¥10 万–40 万、收购资格 ¥20 万–80 万。
2. **背包二选一与防套利设计**：
   - 背包内商品可用于 `⚡` 使用激活增益、`📜` 囤积凑齐收购资格，或直接转售换钱。
   - 转售按**实付价 85%–95%** 回收（用 9 折券购买同样按实付基准计算），期望为负必亏，彻底堵死「9 折买入 + 转售」与「双人互刷」正期望套利；每人每商品每日限购 **3 件**。
3. **客流档位与餐饮差异化**：
   - 店铺累计流水达档后，门口会定期刷新「客源金币」；任意玩家拾取可全额获得面额，店铺收购人按档位额外分成 **30% / 50% / 80%**。
   - **餐饮店（奶茶 / 馄饨 / 咖啡 / 茶馆 / 面包 / 糖水共 6 家）客流档位门槛减半**（如原 ¥2 万档仅需 ¥1 万即达标），用以补偿食品不可转售带来的客流变现差异，体现餐饮业「刚需消耗」的经营特色。

### 体能系统

左下角体能进度条（绿 → 黄 → 红闪烁三级）：

| 状态 | 数值 |
| --- | --- |
| 上限 / 初始 | 100 |
| 普通行走消耗（WASD） | 每 2 秒 -1 |
| 冲刺奔跑消耗（按住 Shift） | 每秒 -2（赶路抢金币 vs 省体能的取舍） |
| 站立保底恢复 | 每 3 秒 +1（没钱时的喘气回能，防死锁） |
| 拾取门槛 | 体能 ≥ 20 才能捡金币 / 金币箱 / 客源金币 |

- 体能不足时拾取被拦截（客户端预拦 + 服务端 `409 体能不足` 双保险），低体能提示每 2 秒节流一次防刷屏
- **低于 20 时禁止冲刺**（Shift 失效只保留普通速度）——没钱没体能也能走到餐饮店门口，永不卡死；实测体能会在 20 附近阻尼稳定，不归零
- **补充能量 = 到店里买食品饮品类商品**（🥤 daily，买完立即恢复）：奶茶 +50、美式咖啡 +65、大排面 +90、馄饨 +80 等——餐饮店刚需闭环的最后一环
- 客户端本地权威（250ms 刷新），每 5 秒上报服务端限幅校验（单次上报最多变化 ±25，防瞬移刷库）
- 窗口失焦 / 退出指针锁定时自动清空按键状态（防切窗回来角色持续移动）

### 商品三类体系

消耗品与流通品去向严格互斥——**绝不允许「既用了效果又卖了货」**：

| 类别 | 去向与限制 | 核心作用 / 明细 |
| --- | --- | --- |
| 🥤 **日常消费**<br>（即食食品饮品） | 买完立即吃喝生效<br>**不进背包、不可转售**（服务端强制拦截） | `👟 健步如飞`（移动速度 +35%）<br>`✨ 财运暴击`（金币雨暴击率 +12%）<br>`🧲 吸金磁铁`（拾取半径 +60%）<br>食品同时**恢复体能 +30~90**（奶茶 +50、馄饨 +80、大排面 +90） |
| ⚡ **功能商品**<br>（进背包，使用制） | 买后入包，需在个人中心点「使用」激活并扣库存；**未使用前可自由转售** | 10 分钟长效增益：<br>`📈 日进斗金`（收租收益 +25%，服务端结算）<br>`💰 点石成金`（拾取金币金额 +30%）<br>以及长效版速度 / 磁铁 / 暴击 |
| 📜 **收购资格**<br>（硬通货材料） | 进背包，**可自由转售**；收购成功时自动消耗并从背包移除 | 商业许可证（金融中心 ¥80 万）<br>街区信誉章（书店 ¥30 万）<br>税务合规书（礼和堂 ¥50 万）<br>装修图纸（记忆馆 ¥20 万）<br>稀有黑胶唱片（赵元任故居 ¥60 万） |

增益生效期间，顶部状态条（`👟 58s` 等徽标）内嵌**倒计时进度条**：剩余时长按本次激活总时长比例递减（250ms 刷新），一眼看清增益还剩多久。

### 分级收购门槛

高级商铺不能纯靠金币买下，资产卡收购面板会逐项实时展示门槛达成情况（`✅` / `❌`），未达标禁止收购；材料仅在收购成功时扣除，失败不消耗。

| 阶段（按收购门槛） | 店铺数量 | 收购条件 |
| --- | --- | --- |
| 第一幕 · 普通店铺 | 7 家 | 仅金币 |
| 第二幕 · 精品店铺 | 4 家 | 金币 + 商业许可证 + 街区信誉章 |
| 第三幕 · 高级店铺 | 3 家 | 金币 + 四证齐全（商业许可证 + 街区信誉章 + 税务合规书 + 装修图纸） |
| 第四幕 · 黄金店铺 | 4 家 | 金币 + 四证 + 稀有黑胶唱片 + 持有店铺数 ≥ 3 |

### 踢馆议价与安全兜底

服务启动时会自动扫表，将上次进程异常中断残留的「进行中踢馆」托管金原路退回攻击方（状态标记为 `refunded`），并自动补齐店铺保护冷却——杜绝服务重启导致托管金蒸发。

### 众筹扩建与分红

第二幕及以上店铺店主可发起扩建众筹：设定总目标与个人出资上限，其他玩家出资入股后按持股比例永久分享该店 **40% 的租金分红**（与店主分润）。众筹完成后店铺等级提升，流水收益与客流刷新频率同步提高；众筹失败原路退款。

## 接入真实 GLB 模型

无需改动业务代码，支持两种方式替换默认程序化建筑：

1. **按建筑逐栋替换（推荐）**：将模型放入 `public/models/`（如 `cafe.glb`），在 `src/data/layout.js` 对应建筑条目加上 `model: 'cafe.glb'`；或将模型按建筑 `id` 命名后通过 `http://localhost:5177/?models=/models` 访问即可自动匹配。加载失败会自动保留原程序化建筑。
2. **整条街替换**：放入 `public/models/street.glb`，通过 `http://localhost:5177/?glb=/models/street.glb` 加载（支持 Draco 压缩，模型命名含 `ground`/`wall`/`shop_<id>` 时会自动识别地面、碰撞体与店铺）。

## 已知限制与后续路线

- **美术与移动端**：仓库暂未附带真实 `.glb` 模型与贴图资源；交互依赖键盘与 Pointer Lock，暂未适配触屏移动端。
- **单机写库瓶颈**：后端默认使用 `sql.js`（内存库全量导出，现 `server/db.js` 已改为 400ms 节流异步原子落盘，但仍勿多进程同时读写同一 `.db` 文件）；早先同步写盘基准上限约 180–190 次/秒，300 人正常游玩稳定，更高并发需后续切换 `better-sqlite3`（WAL）或 MySQL。
- **多进程扩展**：当前踢馆互斥与房间状态依赖单进程内存，未来横向扩展需接入 Redis 分布式锁与实现 `db.js` 的 MySQL 分支。
- **多人同屏渲染**：角色合批与建筑按材质合并后，30 人同房实测 ~51 FPS；若需冲击 60+ FPS，可继续做远端玩家实例化、动态阴影降频或远景合批。
